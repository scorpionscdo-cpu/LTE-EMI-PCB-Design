# Deep Interview — 앱 제작 스킬

사용자와 **깊이 있는 인터뷰**를 진행해 만들 앱의 요구사항을 명확히 한 뒤, 곧바로 동작하는 앱을 만든다. 추측으로 만들지 말고, 핵심 결정은 반드시 질문해서 확정한다.

## 진행 원칙

1. **한 번에 너무 많이 묻지 않는다.** `AskUserQuestion` 도구로 회차당 1~3개의 핵심 질문만 던진다. 각 질문에는 추천 옵션을 먼저 제시한다.
2. **이미 알 수 있는 건 묻지 않는다.** 대화 맥락·기존 코드에서 알 수 있는 사실은 다시 묻지 않는다.
3. **답이 모이면 명세를 한 번 요약**해 보여주고 확인받은 뒤 제작에 들어간다.
4. 사용자가 "알아서 해줘"라고 하면, 합리적 기본값으로 진행하고 무엇을 가정했는지 밝힌다.

## 인터뷰 단계 (순서대로, 필요한 것만)

1. **목적/문제** — 이 앱으로 무엇을 해결하려는가? 누가 언제 쓰는가?
2. **핵심 기능** — 반드시 있어야 할 기능 3~5가지. 입력·처리·출력 흐름.
3. **데이터** — 무엇을 저장하나? 저장 위치(보통 `localStorage`), 항목 구조.
4. **출력/내보내기** — 화면 표시 외에 텍스트 복사, 인쇄, PDF, CSV 등이 필요한가?
5. **디자인** — 분위기(다크/라이트), 한국어 UI 여부, 모바일 대응.
6. **배포** — 단일 HTML 파일로 충분한가? Vercel 등 배포 계획.

## 제작 가이드

- 별도 빌드 없이 바로 열리는 **단일 HTML 파일**(인라인 CSS/JS)로 만든다. 외부 라이브러리·CDN 의존을 피한다(오프라인·한글 안전).
- 데이터 영속화는 `localStorage`를 사용한다.
- PDF가 필요하면 jsPDF 대신 **브라우저 인쇄(`window.print`) + 인쇄용 레이아웃**을 사용한다(한글 깨짐 방지).
- 사용자가 넣는 텍스트는 HTML 출력 시 **이스케이프**한다.
- 이 저장소의 기존 앱(`weekly-report.html`, `calculator.html`)의 다크 테마·코드 스타일과 톤을 맞춘다.
- 파일명은 기능을 드러내는 영문 케밥케이스(`todo-tracker.html` 등).

## 마무리

1. 만든 앱을 짧게 설명한다(주요 기능, 사용법, 저장 방식).
2. 지정된 작업 브랜치에 **커밋·푸시**한다. (PR은 사용자가 명시적으로 요청할 때만)
3. 여러 앱이 생기면 루트 `index.html` 링크 목록과 `vercel.json` 라우팅을 갱신할지 제안한다.
4. 다음에 다듬을 만한 후보 기능을 2~3개 제안한다.
